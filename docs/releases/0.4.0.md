# Nemein v0.4.0 — Revisiones, respaldos externos y contrato de importación

Versión experimental para Windows x64, de código abierto bajo licencia MIT. Incluye las mejoras posteriores a la release 0.3.0.

## Novedades

- Revisiones periódicas: un paquete calculado en una sola lectura con saldos a una fecha de corte, última conciliación por cuenta, metas y pagos recurrentes próximos. Las revisiones guardadas son inmutables, se recalculan al guardar (`REVIEW_STALE` si el libro cambió) y sólo la persona dueña las marca como revisadas. [Revisiones](https://github.com/Danor07/nemein/blob/v0.4.0/docs/revisiones.md).
- Acciones `review-*` con permisos propios, negados por defecto. El texto escrito por agentes se guarda y se muestra como texto plano escapado.
- Respaldos externos: `BUDGET_BACKUP_DIR` envía los respaldos pedidos (CLI o botón) a una carpeta externa ya existente. Las copias de arranque y por hora de la ventana siguen siendo locales, así una unidad ausente nunca bloquea el arranque. [Respaldos](https://github.com/Danor07/nemein/blob/v0.4.0/docs/respaldos.md).
- Contrato de importación único v1: JSON Schema 2020-12 con procedencia, período declarado, moneda, importes enteros e identificador estable para deduplicar, con errores con código. El CSV es su primer productor y conserva su comportamiento: misma previsualización, deduplicación y confirmación atómica. Incluye vectores de prueba para futuros conectores. [Importaciones](https://github.com/Danor07/nemein/blob/v0.4.0/docs/importaciones.md).
- Horas mostradas en la zona y el formato del sistema de quien mira, sin país fijo. Pantalla de revisiones pulida tras revisión visual.
- Seguridad: Node.js incluido actualizado a 22.23.4. La compilación se rechaza con cualquier otra versión, y la CI Linux usa la imagen oficial fijada por digest.
- Migración SQL 6, transaccional, que agrega la tabla de revisiones. Guardar o marcar una revisión no emite `budget.changed`.

## Descargar e instalar

Descargá Nemein-0.4.0-windows-x64-selfsigned-setup.exe y verificá su hash con SHA256SUMS.txt. Requiere Windows x64 y WebView2; incluye Node.js y las dependencias.

El ejecutable y el instalador están firmados con el certificado autofirmado de Innova-tech y sello de tiempo. No es una firma con confianza pública: SmartScreen puede mostrar una advertencia. El archivo .cer es sólo el certificado público; no se importa automáticamente como raíz de confianza.

Abrí el instalador con doble clic desde el Explorador. Evitá iniciarlo desde una terminal de una app MSIX, donde Windows puede redirigir la instalación a una carpeta privada.

## Actualizar

1. Cerrá Nemein y los clientes MCP/CLI y guardá una copia de la carpeta %LOCALAPPDATA%\PresupuestoCero completa.
2. Instalá 0.4.0 desde el Explorador. Se conservan la carpeta de datos y el identificador de instalación; la migración 6 se aplica al abrir.
3. Desde 0.3.0 las conexiones siguen siendo compatibles. Las acciones de revisión comienzan negadas: concedelas expresamente si querés que un agente prepare revisiones.
4. Si venís de versiones anteriores a 0.3.0, seguí también los pasos de las [notas de 0.3.0](https://github.com/Danor07/nemein/releases/tag/v0.3.0).

Volvé a abrir el cliente MCP después de actualizar para que detecte el catálogo nuevo. Esta publicación no instala ni renueva tus conexiones automáticamente.

## Contratos y límites

El contrato de importación v1 es interno al proceso: todavía no hay API HTTP, OFX, camt.053 ni conectores WASM. Esos pasos están planificados sobre este contrato. PYG sigue usando importes enteros y no hay motor cambiario.

Las revisiones no cambian el presupuesto: son un registro de lo que se miró. `BUDGET_BACKUP_DIR` exige una carpeta absoluta existente; si falta, el respaldo pedido falla con salida no cero en lugar de escribir en otro disco.

## Validación y recuperación

La evidencia de regresión, mutación e instalación se detalla en [VALIDACION.md](https://github.com/Danor07/nemein/blob/v0.4.0/VALIDACION.md). Las pruebas usan datos ficticios y presupuestos temporales.

Si una actualización falla al migrar, su transacción se revierte. Antes de volver a una versión anterior, cerrá todos los procesos y restaurá la copia previa completa; no fuerces una versión antigua sobre un esquema futuro ni mezcles archivos WAL. Restaurar un backup también restaura los permisos de ese momento: revisalos antes de reconectar clientes.
